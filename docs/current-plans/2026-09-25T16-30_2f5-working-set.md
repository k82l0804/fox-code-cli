# 2F-5: `/add` Working Set as a First-Class Session Object

> **Loop assertion**: Files in the working set are always included in `buildCodeContextBlock()` pinned body budget with priority over localize-only pins. The working set persists across turns.

---

## Goal

Make the file context sticky across turns. Currently, localize pins rotate every turn — after turn 1, the model may lose the file it just edited. The working set is the union of: localize pins, mutated files, `/add` files, and `--file` flag files. Working set pins have priority over localize-only pins when the 5k token budget is tight.

## Proposed Changes

### 1. Working Set Module (`src/session/working-set.ts` — new)

```typescript
export interface WorkingSet {
  add(file: string, source: "user" | "mutated" | "localize" | "cli"): void
  drop(file: string): boolean
  has(file: string): boolean
  files(): Array<{ file: string; source: string }>
  userFiles(): string[]    // only user-added and CLI files (priority)
  clear(): void
}

export function createWorkingSet(): WorkingSet
```

Session-scoped. Stored in the processor's session state maps (same pattern as `mutationJournals`).

### 2. Auto-Add on Mutation

In `processor.ts`, after `journal.record()` (line ~847), call `workingSet.add(filePath, "mutated")`. This ensures edited files stay pinned.

### 3. Priority in `buildCodeContextBlock()`

Modify `code-context.ts` pin allocation (line ~190):
1. Working set files (source: `user` or `cli`) — always pinned first
2. Working set files (source: `mutated`) — pinned second
3. Localize-only pins — fill remaining budget

When truncating under budget pressure, remove localize pins first, then mutated pins, never user/cli pins (unless they alone exceed the budget).

### 4. `/add` and `/drop` Commands

Register as session commands in the TUI command system:
- `/add <path>` → resolve path relative to project dir, add to working set with source "user", mark `codeContextDirty = true`
- `/drop <path>` → remove from working set, mark dirty
- `/files` or `/ls` → list current working set

### 5. `--file` Flag Integration

In `src/cli/cmd/run.ts`, after processing `args.file`, pass file paths to the session's working set with source "cli".

## Edge Cases

- `/add` non-existent file → error message, not added
- `/drop` file not in set → no-op with info message
- Working set exceeds pin budget → truncate by reverse priority (localize → mutated → user)
- File deleted by model edit → keep in set but skip pinning (file read will fail gracefully)

## Verification Plan

## Non-Goals / Do Not Break

- Local-first: no network calls
- Prefix stability: working set changes trigger cache invalidation (dirty flag), but stable sets keep the same cache key
- Transactional apply: `/add` is not a mutation — no journal entry
