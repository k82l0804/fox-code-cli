## 1. Executive Summary & Context

With all Phase 1 foundations, Phase 1B compression hardening, Phase 2.0 adaptive compression, and Phase 1 remaining items (Named Shadow Checkpoints & Open-Weights Model Profiles) completed and validated across the monorepo, **Fox CLI is ready for Phase 2**.

Phase 2 shifts Fox from a **high-precision, token-compressed interactive CLI** into a **resilient autonomous software engineering agent**.

### The Core Problem Phase 2 Solves
- In interactive mode, **the human is the guardian**: the human reviews diffs, redirects failing strategies, gates risky mutations, and determines when a task is finished.
- In `--auto` mode, **nobody fills that role**. Unsupervised models either enter repetitive thrashing loops, blindly accept regressions, hallucinate completion, or stall when tests fail.
- **Fox Guardian** bridges this gap: a dual-agent oversight pattern where an independent, fast evaluator agent acts as a surrogate for human supervision when running autonomously.

## 4. Phase 2A Detailed Implementation Breakdown

### 4.1 Guardian Agent Core (`packages/core/src/guardian/` or `src/session/guardian/`)

The Guardian is **always present** with **sliding authority** based on user engagement:
- **`advise`** (Interactive mode): Observations and warnings displayed in the TUI status bar; human makes decisions.
- **`enforce`** (Tool-bounded mode `--tools=system`): Intercepts tool loops and injects hints into context.
- **`surrogate`** (Autonomous mode `fox --auto` or `fox run --auto`): Full authority over the doer (gates intake, directs recovery, audits pre-commit diffs).

```typescript
type GuardianAuthority = "advise" | "enforce" | "surrogate"

interface GuardianService {
  readonly authority: GuardianAuthority
  
  // Hook A1: Post-Failure Analysis
  classifyFailure(input: GuardianFailureInput): Effect.Effect<GuardianFailureDecision>
  
  // Hook A2: Pre-Commit Review Gate
  reviewChanges(input: GuardianReviewInput): Effect.Effect<GuardianReviewDecision>
  
  // Hook A3: Periodic Progress Audit
  checkProgress(input: GuardianProgressInput): Effect.Effect<GuardianProgressDecision>
  
  // Hook A4: Resumption Wake-Up Audit
  auditInterruptedSession(session: SessionInfo): Effect.Effect<WakeUpBriefing>
}
```

#### Decision Point A1: Post-Failure Classification
- **Trigger**: Verification command fails post-mutation.
- **Action**: Guardian receives compressed failure output (LLTC filtered) + last 3 actions.
- **Output**:
  - `failureType`: `"syntax" | "type" | "assertion" | "runtime" | "environment" | "design"`
  - `action`: `"continue" | "switch_strategy" | "escalate" | "stop"`
  - `strategyHint`: e.g., *"Import path missing; do not edit logic, resolve symbol in index.ts."*

#### Decision Point A2: Pre-Commit Review Gate
- **Trigger**: Doer signals completion and all tests pass.
- **Action**: Guardian audits cumulative diff from `Checkpoint.Service` or `Snapshot.Service`.
- **Output**:
  - `action`: `"approve" | "request_changes" | "flag_for_human"`
  - `concerns`: List of unaddressed acceptance criteria, dead code, or unintended edits.

#### Decision Point A3: Periodic Progress & Trajectory Audit
- **Trigger**: Every $N$ doer turns (default 10).
- **Action**: Guardian evaluates goal alignment, budget spend, and file mutation trajectory.
- **Output**:
  - `action`: `"continue" | "refocus" | "stop"`
  - `refocusHint`: Corrective guidance if the doer is drifting into tangential refactors.

#### Decision Point A4: Interruption Recovery & Wake-Up Audit
- **Trigger**: Session launched with `--continue` after crash or abort.
- **Action**:
  1. Triage dangling tool calls in SQLite as `{ status: "error", interrupted: true }`.
  2. Git reconciliation against baseline tree snapshot.
  3. Pre-populates ready-to-run prompt in TUI composer or resumes autonomous execution immediately.

### 4.2 Auto-Verification Execution Pipeline (Blueprint 3a)
- **Current State**: `VerificationDetector.Service` discovers the best test command (e.g. `bun test`, `pytest`, `cargo test`).
- **Phase 2A Task**:
  1. Hook into `processor.ts` post-mutation.
  2. When in autonomous mode (`--auto`), automatically execute the detected test command non-interactively with a safety timeout.
  3. Pipe stdout/stderr through `filterTestOutput` (LLTC) to strip repetitive passing runs and compress failures before passing to the doer and Guardian.

---

### 4.3 Checkpoint ↔ Oscillation Recovery (Blueprint 3d)
- **Current State**: `oscillation.ts` detects $A \to B \to A$ cycles; `Checkpoint.Service` stores shadow git tree snapshots and selective rollback.
- **Phase 2A Task**:
  - Wire them together: when oscillation is detected or `RepairBudget` is exhausted ($N \ge 3$ consecutive failures without progress):
    1. Guardian recommends rollback.
    2. Session automatically invokes `Checkpoint.Service.undo()` to revert files back to the pre-failure snapshot.
    3. Fresh context prompt is injected instructing the doer that the approach failed and a clean alternative is required.

---

### 4.4 Multi-Model Routing Policy Engine (Blueprint 4)
- **Concept**: Use fast, cost-effective models for initial implementation, escalating to frontier reasoning models when stuck.
- **Corporate Model Profile Alignment**:
  - **Fast Coder / Doer**: `codestral` (Mistral 22B) or `llama-3.1-8b` / `gemma-4-31b`
  - **Guardian Evaluator**: `gemma-4-31b` (sub-100ms evaluation)
  - **Escalation Reasoning Model**: `nemotron-3-ultra-550b` or `gpt-oss-120b` (or Gemini 3.1 Pro via proxy)
- **Escalation Trigger**: 2 consecutive failed turns + Guardian `action: "escalate"` $\to$ switches doer context to the escalation model for a single deep-reasoning recovery turn.

## 5. Architectural Constraints & Non-Negotiables

1. **Non-Chinese Models Only**: Maintain strict adherence to corporate policy (no Qwen, DeepSeek, Yi, GLM; utilize Western open-weights: Meta Llama 3.1/3.3, Mistral/Codestral, Google Gemma, Nvidia Nemotron, OpenAI GPT-OSS).
2. **Zero Git Log Pollution**: All internal checkpoints, baselines, and diffs must use `Checkpoint.Service` and `Snapshot.Service` shadow trees (`refs/fox/checkpoints/*`). User repository history remains clean.
3. **Hard-Coded Circuit Breakers Stay Separate**:
   - SHA-256 oscillation, timeouts, doom loops, and repair budgets are **fuse-box circuit breakers**.
   - The Guardian is the **reasoning brain**. The fuse box overrides the brain if the LLM hallucinates.
4. **Token & Latency Budget**: Guardian prompts must stay concise ($\le 350$ tokens in, structured JSON out) with latency $<1.5\text{s}$ so turn overhead is negligible ($<2\%$ total token budget).
5. **Anti-Hang Shell Execution**: Non-interactive commands only, `GIT_TERMINAL_PROMPT=0`, task-appropriate `timeout` prefixes.
